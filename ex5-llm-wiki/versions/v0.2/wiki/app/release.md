# Релиз — release

## Назначение

Изменения в [системах](app.md) реализуются в рамках релизов. Для каждой затрагиваемой системы нужно понимать, какие работы по запросу запланированы и в каком выпуске они будут реализованы.[^email-01]

Алиса предлагает выделить релиз как агрегат контекста [app](context.md).[^email-02]

## Предлагаемый состав

- Связь с системой.
- Состав работ по изменениям и ссылки на соответствующие [RFC](../change/rfc.md).
- Состояние релиза.
- Результат выпуска.[^email-02]

Точные атрибуты, набор состояний и правила переходов в письмах не определены.

## Допущение

Один релиз относится к одной системе. Это предварительное предложение Бориса, поддержанное Алисой; оно требует подтверждения.[^email-01][^email-02]

## Связь с выполнением запроса

Релизы разных систем могут выходить в разное время. Выпуск одного релиза не означает выполнение всего RFC, если запрос затрагивает несколько систем. После выпуска фиксируется результат соответствующей части изменения.[^email-01]

По предложению Алисы сведения о включении работ в выпуск и результатах реализации передаются в [change](../change/context.md).[^email-02]

## Вопросы для уточнения

Не определено, может ли релиз включать работы по нескольким RFC и может ли реализация одного RFC в одной системе распределяться между несколькими релизами.[^email-01]
