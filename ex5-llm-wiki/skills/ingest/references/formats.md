# Форматы ingest

## Выбор шаблона

Сначала найди в `schema` файл с `template_for`, равным типу страницы. При нескольких соответствиях уточни выбор. Если шаблона нет, используй файл навыка:

| Тип | Шаблон |
|---|---|
| Aggregate | [aggregate.md](../templates/aggregate.md) |
| Entity | [entity.md](../templates/entity.md) |
| Value Object | [value-object.md](../templates/value-object.md) |
| Actor | [actor.md](../templates/actor.md) |
| Command | [command.md](../templates/command.md) |
| Event | [event.md](../templates/event.md) |
| Relationship | [relationship.md](../templates/relationship.md) |
| Bounded Context | [bounded-context.md](../templates/bounded-context.md) |

Каждое выделенное понятие отражается в существующей или новой странице. Отношение всегда отражается в таблицах связей обоих концов; отдельная страница нужна, если у отношения есть собственные правила, атрибуты или неоднозначности. Команда означает намерение выполнить действие; событие — произошедший факт. Actor — роль участника, а не обязательно человек. Тип и тождественность понятия определяются по смыслу и свидетельствам.

В экземпляре замени `type: Template` на целевой тип, удали `template_for` и добавь метаданные из [frontmatter.md](../templates/frontmatter.md). Заполнители заменяй фактами либо «Не определено». Не копируй инструкции шаблона в страницу.

## index.md

Используй [шаблон индекса](../templates/index.md). После заголовка «Индекс wiki» размещается один блок `text` с псевдографическим деревом. Без frontmatter, таблиц, вложенных Markdown-списков и inline code внутри рисунка.

- Корневая строка — `wiki/`; остальные строки содержат префикс дерева, имя файла или каталога и комментарий через ` — `. Каталоги заканчиваются `/`.
- Используй `├──`, `└──`, `│` и обычные пробелы: четыре позиции на уровень. Вертикальная линия продолжается только там, где есть следующий сосед. Последний элемент уровня начинается с `└──`.
- Комментарии начинаются в одной колонке: ширина самого длинного префикса с именем плюс два пробела. Все строки, включая каталоги и служебные файлы, имеют комментарий.
- Комментарий страницы — читаемое название и краткое содержание, суммарно до 100 символов. Не повторяй одно и то же в названии и содержании; сокращай на границе слов. Для каталога укажи ответственность группы.
- Сортируй соседей: сначала каталоги, затем файлы; внутри групп — лексикографически по имени Unicode. Каждый объект wiki представлен один раз, включая скрытые файлы и вложения. Не следуй символическим ссылкам за пределы wiki.
- Поскольку ссылки внутри блока кода не работают, не вставляй туда Markdown-ссылки. Относительный путь восстанавливается по дереву; ссылки между понятиями остаются в страницах.
- Источники и внешние архивы в дерево не включай. Для `index.md` комментарий — «Индекс — дерево файлов wiki»; для `log.md` — «Журнал — время, операция и содержание изменений».
- При доступном предпросмотре проверь непрерывность линий и выравнивание комментариев. Если в узком окне требуется горизонтальная прокрутка, сохраняй выравнивание дерева, не разбивай его на таблицу.

## log.md

Используй [шаблон журнала](../templates/log.md). Без YAML frontmatter. После заголовка «Журнал изменений» размещается одна Markdown-таблица: `Время`, `Файл`, `Операция`, `Содержание изменения`. Одна фактическая модификация файла за запуск — одна физическая строка таблицы.

- **Время:** фактическое время успешной модификации, ISO 8601 с секундами и смещением `±HH:MM`. Часовой пояс пользователя; при неизвестном — UTC `+00:00`. Не подставляй дату исходного документа.
- **Файл:** Markdown-ссылка с полным путём от корня хранилища, начинающимся с `wiki/`. Цель ссылки — относительно `wiki/log.md`. Разделители путей — `/`; специальные символы в URL кодируются.
- **Операция:** выбери основной вид правки: `Создание`, `Дополнение`, `Уточнение`, `Исправление`, `Переформатирование`, `Миграция`, `Метаданные` или `Устаревание`. Не используй общее «Изменение». Для смешанной правки перечисли дополнительные действия в содержании.
- **Содержание изменения:** одно конкретное предложение, что добавлено, исправлено, уточнено или заменено. До 200 символов; при нескольких правках одного файла перечисли основные через точку с запятой. Например: «Добавлены условия повторного рассмотрения и ссылка на распоряжение», а не «Обновлён файл» или «Выполнен ingest». Для новой страницы укажи её предмет и ключевые сведения; для метаданных — какие поля изменились.
- Описание выводи из реальной разницы до/после. Правка только метаданных не описывается как изменение бизнес-правил. Если важно, назови исходный документ или уточнённое правило; контрольные суммы остаются в frontmatter страницы.
- Дописывай строки в конец в порядке фиксации. Неизменённые файлы не логируй. Несколько промежуточных записей одного файла объединяй в одну итоговую строку. Для индекса пиши, какие группы или страницы добавлены либо изменено оформление.
- Для самого `wiki/log.md` добавь одну последнюю строку об общей дописанной порции, например «Добавлены записи о пяти изменённых файлах». Она не вызывает рекурсивного логирования.
- Экранируй `|` как `\|`, переводы строк заменяй пробелами. Не используй многострочные ячейки, списки внутри таблицы или дополнительные поля.

При миграции прежних строк сохрани время и путь. Сначала проверь достоверную историю работы и разницу с доступными архивными версиями: наличие исходной версии позволяет восстановить операцию и содержание без выдумок. Текущее состояние файла само по себе не доказывает прошлую правку. Если содержание исторической правки неизвестно, операция — `Не указано`, содержание — «Содержание изменения ранее не фиксировалось». Это значение допускается только для старых записей. Не восстанавливай содержание только по текущему тексту файла и не придумывай точное время. Историю, которую нельзя перевести без потерь, сохрани отдельно; явное поручение применить новый формат разрешает такую миграцию с сохранением исходника.
